# Tape Lounge — observation-led redesign

## Product structure

The primary navigation is **라운지 / 마켓 / 리서치**. Existing features remain available:

- Lounge: compact quotes, return summary, chart, Andy observations, shared favorites,
  session and calendar context, research links, highlights and conversation.
- Market: the original domestic/foreign comparison table, search, favorites and Andy
  badges. Its data transports and freshness limits are preserved.
- Research: three strategist reports and a searchable observation ledger. On-chain,
  calendar, chart studies and the futures desk are detail screens, not primary tabs.
- Spectator effects and paper trading are collapsed, opt-in lounge sections. Blind
  charts remain available from the Playroom and More menu.

`#market` and `#research` are canonical navigation hashes. Old `#domestic` and
`#strategists` links continue to work. Existing detail hashes are preserved. The
analytics RPC still receives its original tab names; no schema or permission change.

## Implementation

`lounge-v2.js` constructs the new layout before the original chart/canvas engines
measure their containers. Existing chart, chat, game and market IDs and lifecycle
handlers are reused. `lounge-v2.css` supplies the responsive editorial dark theme.
No framework, new service, paid API or hosting migration is introduced.

- Default chart: 4h, with all original timeframes available. SMA 5/20/60/120/200,
  Supertrend, synchronized MACD/RSI and long BTC channels remain intact.
- Favorites use the existing `tl_domestic_favorites` browser key and synchronize
  between the lounge and market and across browser tabs through local events.
- A symbol opens a Binance **spot** chart and its observation timeline in a dialog.
  The futures desk is separately labeled. No order endpoint is called.
- A return comparison uses `tl_lounge_visit_v2` in this browser only. It compares
  actual saved quote observations and report states, labels their timestamps, and
  requires a prior observation at least 15 minutes old. No historical price is invented.
- Spot quotes refresh at most once a minute while the lounge is visible. They also
  fill the original price displays when trade streams have not produced recent data.
  The visible chart falls back to periodic REST reseeding if its stream is silent.
- Report/ledger/calendar reads are cached and refreshed while visible. Fetches are
  bounded by a timeout and cancelled on leaving the relevant screens.
- Race streams and particle/full-screen effects require the spectator section to
  be open. Closing it stops subsequent animation frames. Original market recording
  and order-flow calculations remain separate from visual effects.
- Human/all conversation filters affect display only; no messages are removed.

## Andy observation ledger

`scripts/build_andy_watch.py` reads **already published HTML reports**. It uses only
Python's standard library, Git and local files. It never imports the trading system,
contacts exchanges, reads account configuration, or sends Telegram messages.

`data/andy-watch.json` includes the report timestamp, source content hash, up to 90
report snapshots, current candidates, removed entries and their observed transitions.
Initial seeding inspects the last 90 days of report commits (maximum 100 commits).
Subsequent daily publishing uses `--current-only` to append the new report to the
preserved ledger. The output is written atomically.

The scanner publisher calls this builder after copying the generated public report
and stages `data/andy-watch.json` with that report. It does not run another scan.
If building the ledger fails, that publication fails rather than silently presenting
a successful current report with a broken update path. This hook is inside the
existing explicitly enabled publishing path; deployment does not invoke the scanner.

Interpretation rules:

- `firstSeenAt` is the first observation **within the retained report coverage**.
- Daily and 4h observations for the same symbol are separate records.
- `목록 제외` means absent from the next report. It is not a stop, sale, failed
  support, or realized loss. The scanner universe and data availability can change.
- Prices/support distances in reports are snapshots, not current support levels.
- No trade returns, hit rate, or reconstructed historical trading performance is
  calculated from the ledger.
- A report older than 36 hours is labeled old. Missing data is shown as unavailable,
  not as zero candidates or a successful scan.

## Verification and rollback

Implementation checks: JavaScript syntax, whitespace errors, builder execution on
real report history, browser accessibility/DOM inspection, quote fallback, candidate
dialog/timeline, favorite saving, market badge loading, ledger filters and mobile
390px layout. Browser screenshot capture was unavailable in this environment;
visual pixel-level screenshot review could not be completed.

No manual orders, scanner run, Telegram post, model training, bot restart, account
mutation, or analytics schema migration is required by this redesign.

Rollback should revert the UI commit and the scanner's two ledger hook changes
together. Preserve any newer report data and `andy-watch.json` history when reverting
code; never hard-reset an active publisher checkout to an old data commit.
